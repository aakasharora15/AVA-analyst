# AVA: Adversarial Venture Analyst

Clickable front-end prototype of AVA, a venture-risk platform for VC funds, corporate venture teams and accelerators. Six agents attack a venture in a fixed order; code computes a Resilience Score (0 to 100, higher is better) and one directive: PROCEED, HOLD, PIVOT or KILL.

All data is mocked. Screens only call `src/data/repo.js`, so it can be swapped for Supabase without touching the UI.

## Run

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # Vitest: engine, router, renderer
npm run build && npm run preview
npm run mock       # regenerate src/data/mock/*.json through the real engine
```

Deep links work on refresh in `dev`, `preview` and on Vercel (`vercel.json` rewrites to `index.html`).

## Stack

- Vite, vanilla JavaScript (ES modules), plain CSS with custom properties. No UI framework.
- `src/router.js`: History API router with `:param` segments, hash scrolling, focus management.
- `src/lib/html.js`: tagged-template renderer that escapes interpolated values.
- `src/lib/storage.js`: `localStorage` for light conveniences, every access in try/catch.

## Structure

```
src/
  engine/            scoring code, pure functions, all values marked [CALIBRATE]
    config.js        agents, sections, categories, severity and category weights per type, cap, bands
    score.js         exposure, score, cap, base directive, override validation, Partial cap,
                     score excluding dismissed, individual effects, trace
    compare.js       finding matching by match key, category movement, previously dismissed
    alerts.js        band-edge margin, override anchoring, calibration suppression, hold mode
    outcomes.js      checkpoints, outcome status, agreement rate
  data/
    repo.js          async data layer (swap for Supabase), permissions matrix, audit log
    bank.js          finding text for generated audits
    mock/*.json      generated by scripts/generate-mock.mjs
  components/        headers, footer, logo, sheet (dialog), notification panel, helpers
  screens/           one module per screen: { title, load?, render, mount? }
  styles/            tokens, base (moving background), components, app shell, screens
scripts/             mock data generator
tests/               Vitest
```

## Engine rules (spec 4.0)

- Exposure per category = sum of finding severity weights (HIGH 22, MEDIUM 12, LOW 5), capped at 100. `[CALIBRATE]`
- Score = 100 minus the weighted average exposure, with category weights per venture type. `[CALIBRATE]`
- Cap rule: any category above 85 limits the score to 39. `[CALIBRATE]`
- Bands (spec starting values): KILL 0 to 34, PIVOT 35 to 44, HOLD 45 to 64, PROCEED 65 to 100.
- Order: score to base directive, then a valid Orchestrator override (one band down, citing finding ids; anything else rejected and logged), then the Partial cap at HOLD (never raises a lower directive).
- Alerts: score-driven directive changes need a 2-point margin past the band edge; override-driven ones need a cited HIGH finding that is new or unchanged; score and directive alerts are suppressed across calibration versions and directive alerts pause in hold mode.

## Mock data

Ten fictional companies across three venture types, with two to four audits for eight of them. Northline Cold Chain (Leeds, 41, PIVOT) is the main sample, with handwritten findings. The data includes:

- an Orchestrator override (Brightwell Homes);
- a Partial audit capped at HOLD (Ostra Media);
- a failed audit (Tessel Learning);
- compares across calibration versions;
- outcomes that agree and disagree;
- alerts generated by the engine.

Client marks on the Landing marquee are placeholders.

## Prototype controls

- Running screen: "Debug: simulate a failure" makes an agent fail, and optionally its retry, to show the Partial or Failed state.
- Account, Team and roles: "view the app as" switches role to check the permission matrix.
- Account, Profile: "Reset demo data" restores the seed data.
- Sign in: `?state=verify|forgot|reset|reset-expired|sso-not-configured|sso-error|invite-expired` shows each auth state.

## Not in this build

Server-side work stays for the backend build: Supabase row-level security, emails, the calibration harness, shadow re-runs and drift reports, and real agent calls. The UI already shows where each lands (for example the "Under review" banner and hold-mode alert pause).
